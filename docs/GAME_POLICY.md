## 1.2 화면 대응 정책

- 디바이스 화면 크기에 따라 게임 화면을 비율에 맞게 확대 및 축소한다.
- 화면 크기가 달라도 캐릭터 이동 속도, 점프 거리, 장애물 간격 등 게임 조건은 동일하게 유지한다.
- 화면 비율을 유지하며 남는 영역은 여백으로 처리한다.
- 모바일 세로 모드에서는 가로 모드 전환 안내를 제공한다.
- 플레이 중 세로 모드로 변경하면 게임을 일시정지한다.
- 가로 모드로 복귀하더라도 자동으로 플레이를 재개하지 않는다.
- 화면 확대, 스크롤 등 브라우저 기본 동작이 게임 조작을 방해하지 않도록 처리한다.

## 3.2 시작 예외 처리

- 리소스 로딩이 완료되기 전에는 게임 시작 버튼을 비활성화한다.
- 시작 버튼을 연속으로 선택해도 게임은 한 번만 시작한다.
- 카운트다운 중 점프 및 슬라이딩 입력은 반영하지 않는다.
- 게임 시작 직후 최소 3초간 장애물을 등장시키지 않는다.
- 이전 플레이에서 발생한 장애물, 아이템, 충돌 상태 등을 초기화한다.
- 누적 재화와 최고 기록은 초기화하지 않는다.

## 6.2 체력 변화 예외 처리

- 체력이 1인 상태에서 피해를 받으면 즉시 게임 종료 처리한다.
- 체력이 음수로 표시되지 않도록 한다.
- 게임 종료 확정 이후에는 체력이 회복되거나 추가 감소하지 않는다.
- 동일한 시점에 회복 아이템 획득과 장애물 충돌이 발생하면 충돌을 우선 처리한다.
- 충돌로 체력이 0이 된 경우 해당 시점의 회복 아이템은 적용하지 않는다.

회복 아이템은 Phase 03에서 구현한다.

## 7.4 장애물 배치 제한

- 점프 후 착지할 수 있는 공간을 확보한다.
- 슬라이딩 종료 후 다음 장애물을 회피할 수 있는 시간을 확보한다.
- 높은 지상 장애물 바로 뒤에 공중 장애물을 배치하지 않는다.
- 회피 방법이 상충하는 장애물을 동시에 배치하지 않는다.
- 장애물 앞에 충분한 반응 시간을 제공한다.
- 생성 간격은 현재 이동 속도와 캐릭터 조작 가능 시간을 고려한다.
- 장애물이 겹치거나 배경에 가려지지 않도록 한다.
- 모든 장애물은 기본 캐릭터 능력치로 회피 가능해야 한다.

초기 버전에서는 순수 무작위 생성보다 사전에 정의된 안전한 장애물 패턴을 무작위로 선택하는 방식을 사용한다.

# 08. 충돌 및 무적 정책

## 8.1 충돌 판정

| 정책 ID | 항목 | 정책 |
| --- | --- | --- |
| HIT-001 | 판정 방식 | 캐릭터와 장애물의 충돌 영역 비교 |
| HIT-002 | 이미지 투명 영역 | 충돌 영역에서 제외 |
| HIT-003 | 충돌 피해 | 체력 1 감소 |
| HIT-004 | 동일 장애물 중복 피해 | 허용하지 않음 |
| HIT-005 | 충돌 후 무적 | 2초 |
| HIT-006 | 무적 중 추가 피해 | 미적용 |
| HIT-007 | 충돌 후 이동 | 달리기 유지 |
| HIT-008 | 무적 상태의 아이템 획득 | 가능 |

## 8.2 충돌 영역 기준

- 캐릭터의 털, 꼬리 등 외곽 장식은 가능한 한 충돌 영역에서 제외한다.
- 실제 몸체보다 충돌 영역을 다소 작게 설정하여 사용자에게 불합리한 충돌 판정을 방지한다.
- 슬라이딩 상태에서는 충돌 영역의 높이를 축소한다.
- 점프, 착지, 슬라이딩 등 상태 변경 시 충돌 영역을 즉시 갱신한다.
- 고속 이동 중 장애물을 통과하면서 충돌 판정이 누락되지 않도록 처리한다.

## 8.3 무적 상태

- 충돌 직후부터 2초 동안 추가 피해를 받지 않는다.
- 캐릭터 깜빡임 등 시각적 효과를 적용한다.
- 점프와 슬라이딩 조작은 정상적으로 사용할 수 있다.
- 무적 시간은 실제 게임 진행 시간을 기준으로 계산한다.
- 일시정지 중에는 무적 시간이 감소하지 않는다.
- 동일 장애물은 최초 접촉 이후 피해를 다시 발생시키지 않는다.
- 무적 중 접촉한 장애물도 해당 접촉 이후 추가 피해 대상에서 제외한다.
- 게임 종료 및 재시작 시 무적 상태를 초기화한다.

| ITEM-P03 | 배치 방식 | 개별 또는 패턴 단위 |

| ITEM-P05 | 중복 획득 | 허용하지 않음 |
| ITEM-P06 | 미획득 아이템 | 화면 좌측 이탈 시 제거 |
| ITEM-P07 | 일시정지 중 이동 | 정지 |

## 9.3 생선 배치 패턴

| 패턴 | 설명 |
| --- | --- |

| 고공형 | 2단 점프를 통해 획득 |
| 장애물 연계형 | 장애물 회피 경로에 배치 |

## 9.4 아이템 배치 제한

- 장애물 충돌 영역 내부에 아이템을 배치하지 않는다.
- 정상 조작으로 도달할 수 없는 위치에 배치하지 않는다.
- 아이템이 장애물과 혼동되지 않도록 시각적으로 구분한다.
- 아이템 획득 시 즉시 화면에서 제거한다.
- 획득 효과 및 점수 증가 연출을 제공한다.

## 10.1 이동 거리

기본 속도 300px/s 기준으로 초당 10m 이동한다.

## 10.2 점수 계산

| 항목 | 점수 |
| --- | --- |
| 이동 거리 1m | 1점 |
| 생선 1개 | 10점 |
| 장애물 회피 | 별도 점수 없음 |
| 장애물 충돌 | 점수 차감 없음 |

최종 점수 = 정수 이동 거리 + (획득 생선 수량 × 10)

## 10.3 점수 처리

- 점수는 정수 단위로 표시한다.
- 획득한 생선 점수는 즉시 반영한다.
- 게임 종료 후에는 점수를 변경하지 않는다.
- 일시정지 중에는 점수가 증가하지 않는다.
- 최종 점수가 기존 최고 점수보다 높은 경우 최고 기록을 갱신한다.
- 기존 최고 점수와 동일한 경우 신규 기록으로 처리하지 않는다.
- 최고 점수와 최장 이동 거리는 별도로 관리한다.

- 난이도 변경 시 기존 점수, 체력 및 재화는 유지한다.

- 장애물 배치 안전성은 난이도별 생성 간격보다 우선 적용한다.

## 13.1 종료 유형

## 13.2 정상 종료 처리 순서

1. 체력 0 확인
2. GAME_OVER 상태 전환
3. 캐릭터 조작 차단
4. 이동 거리 및 점수 증가 중단
5. 장애물 및 아이템 생성 중단
6. 게임 진행 정지
7. 게임 결과 확정
8. 최고 기록 비교 및 갱신
9. 획득 재화 정산 및 저장
10. 결과 화면 표시

## 13.3 종료 예외 처리

- 게임 종료 로직은 플레이당 한 번만 실행한다.
- 체력 0 이후 발생하는 충돌은 무시한다.
- 체력 0 이후 접촉한 아이템은 획득 처리하지 않는다.
- 게임 종료 시점에 점수와 이동 거리를 확정한다.
- 결과 화면을 반복 호출해도 보상이 중복 지급되지 않도록 한다.
- 결과 화면에서 다시 시작하는 경우 이전 플레이 결과와 신규 플레이 데이터를 분리한다.

# 14. 재화 정산 정책

## 14.1 재화 구분

| 구분 | 설명 |
| --- | --- |
| 획득 생선 | 현재 플레이에서 획득한 생선 |
| 보유 생선 | 이전 정상 종료까지 누적된 생선 |
| 정산 생선 | 게임 정상 종료 시 보유 생선에 반영되는 수량 |

## 14.2 정산 기준

정산 후 보유 생선 = 기존 보유 생선 + 현재 플레이 획득 생선

| 발생 조건 | 보유 재화 반영 |
| --- | --- |
| 플레이 중 생선 획득 | 미반영 |
| 일시정지 | 미반영 |
| 정상 게임 오버 | 반영 |
| 게임 중 재시작 | 미반영 |
| 메인 화면으로 중도 이동 | 미반영 |
| 브라우저 새로고침 | 미반영 |
| 브라우저 종료 | 미반영 |

## 14.3 중복 정산 방지

- 플레이 시작 시 고유 플레이 ID를 생성한다.
- 정상 종료 시 해당 플레이 ID의 정산 여부를 확인한다.
- 이미 정산된 플레이는 재정산하지 않는다.
- 보유 재화, 최고 기록, 정산 플레이 ID를 하나의 저장 데이터로 관리한다.
- 저장 완료가 확인되지 않은 경우 사용자에게 저장 실패 안내를 제공한다.

- 사용자에게 데이터가 저장되지 않았음을 안내한다.
- 현재 실행 중에는 확정된 게임 결과를 유지한다.
- 저장 재시도 시 동일 플레이의 보상이 중복 반영되지 않도록 한다.

- 일시정지 및 재개 정상 동작
- 게임 종료 및 재시작 정상 동작
- 최고 기록 및 재화 저장
- 보상 중복 지급 미발생
- 브라우저 새로고침 이후 저장 데이터 유지
- 반복 플레이 중 이전 플레이 데이터 잔존 오류 미발생
- 플레이를 중단시키는 주요 오류 없음

# 21. 변경 관리 정책

- 게임 기획안 및 게임 정책서를 기준으로 개발한다.
- 정책에 없는 기능을 임의로 구현하지 않는다.
- 기존 정책 변경이 필요한 경우 변경 사유와 영향 범위를 정리한다.
- 이동 속도, 점프 높이, 무적 시간, 장애물 생성 간격 등 밸런스 수치는 별도 설정값으로 관리한다.
- 밸런스 수치 변경 시 관련 기능의 영향도를 검토한다.
- 수정된 정책은 문서 버전 및 변경 이력에 반영한다.
